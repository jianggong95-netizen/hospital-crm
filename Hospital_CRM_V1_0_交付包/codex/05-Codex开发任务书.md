# Codex开发任务书：Hospital CRM V1.0

## 1. 开发总目标
依据本仓库的总体实施方案、数据库设计和OpenAPI契约，逐模块开发医院CRM。不得跳过设计、测试和验收，不得一次性生成全部代码。

## 2. 强制开发规则
1. 开始任务前阅读README、总体方案、数据库设计、OpenAPI和本任务书。
2. 先检查现有仓库结构和代码，不覆盖已有实现。
3. 每个任务先输出：影响范围、数据表、API、页面、权限、测试计划和风险。
4. 等待用户确认后再执行较大范围修改。
5. 使用Flyway或Liquibase管理数据库迁移；禁止只修改初始化SQL而没有迁移脚本。
6. 所有API遵守OpenAPI；实现后同步更新YAML。
7. 所有写接口校验权限、输入、状态机和幂等键。
8. 不得在代码、日志、测试数据和Git中写入真实患者隐私、生产密码、证书或支付密钥。
9. HIS适配器默认只读；禁止任意SQL执行接口。
10. 不得把AI生成结果直接当作医疗诊断或治疗建议。
11. 每个模块必须有单元测试、集成测试、权限测试和关键流程验收测试。
12. 完成后输出变更文件、迁移方式、测试结果、未完成项和风险。

## 3. 技术基线
- Java 21、Spring Boot 3.x。
- PostgreSQL 16+、Redis、RabbitMQ、MinIO。
- Vue 3、TypeScript、Element Plus。
- uni-app + Vue 3，小程序和H5共用业务层。
- OpenAPI 3.1。
- Docker Compose内网部署。
- Maven多模块或Gradle多模块由初始化任务确定，整个项目保持一致。

## 4. 任务清单

### CRM-001 项目初始化
交付：代码仓库结构、后端启动、管理端启动、移动端启动、Docker开发环境、README。
验收：本地可一键启动；健康检查可用；CI执行构建和测试。

### CRM-002 认证、组织、角色、权限
交付：用户、组织、角色、权限、数据范围、登录、令牌刷新、审计。
验收：未授权请求被拒绝；角色权限和数据范围生效；敏感操作有审计。

### CRM-003 客户中心
交付：客户档案CRUD、身份字段加密、脱敏、检索、标签、来源。
验收：客户可创建、查询、更新；手机号和证件检索使用hash；列表不泄露明文敏感字段。

### CRM-004 家庭账户
交付：家庭创建、成员关联、关系历史、家庭管理员、代办授权、撤销。
验收：家庭关系不自动授予病历权限；撤销授权后代办接口拒绝访问。

### CRM-005 HIS SQL Server适配器
交付：连接配置、只读账号校验、患者查询、映射配置、超时、熔断、日志。
前置条件：医院提供测试环境、接口/视图清单、字段字典、患者主索引规则。
验收：无写权限；SQL参数化；查询审计；错误可追踪；无真实数据进入测试仓库。

### CRM-006 患者360
交付：CRM与HIS聚合视图、数据来源和更新时间、字段权限、分页和缓存策略。
验收：不同角色看到的数据范围不同；HIS不可用时明确显示数据过期/暂不可用，不伪造数据。

### CRM-007 客户运营、邀约与分诊
交付：线索、来源渠道、邀约任务、联系记录、分诊转派、活动参与。
验收：线索转客户可追溯；重复线索提示合并核验。

### CRM-008 预约中心
交付：预约类型、服务时段、预约、改期、取消、提醒、爽约记录。
验收：并发预约不超卖；取消规则生效；提醒失败可重试。

### CRM-009 陪诊服务
交付：陪诊师档案、资质、排班、服务区域、派单、接单、计时、完成、评价。
验收：排班冲突被阻止；服务时间可追踪；订单状态只能按状态机流转。

### CRM-010 上门服务
交付：服务目录、地址、资质校验、审核、派单、执行记录、异常上报。
验收：不具备资质人员不能接单；项目审核规则生效；医疗服务异常可升级。

### CRM-011 订单、收费、支付与退款
交付：统一订单、订单项、支付单、回调、退款、对账、发票接口抽象。
验收：重复回调不重复入账；金额校验；部分退款正确；CRM收费不写HIS收费表。

### CRM-012 会员、充值、次卡与套餐
交付：会员等级、余额账本、积分、次卡、套餐、共享授权、扣次与返还。
验收：并发消费不超扣；每次变动有账本；退款按规则返还权益。

### CRM-013 随访中心
交付：分类、模板、计划、自动触发、任务分配、记录、异常升级。
验收：任务按规则生成；重复事件不重复创建；高风险回答进入人工队列。

### CRM-014 投诉表扬中心
交付：工单、等级、分派、处理动作、整改、患者反馈、复核、结案、超时升级。
验收：处理人与结案审核可分权；超时自动升级；所有动作留痕。

### CRM-015 在线客服与人工工作台
交付：会话、消息、客服队列、分配、转接、接管、会话历史。
验收：人工接管保留AI上下文；队列状态准确；会话权限隔离。

### CRM-016 AI知识库与数字人
交付：知识库、文件上传、解析、切片、审核、版本、RAG检索、引用来源、AI随访。
验收：AI答案可追溯知识来源；低置信度转人工；知识失效可下架；不得输出未经授权的患者数据。

### CRM-017 呼叫中心与短信
交付：呼叫中心适配器、来电弹屏、通话记录、录音索引、短信模板、消息Outbox。
前置条件：医院确认呼叫中心厂商API、录音存储和短信服务商协议。
验收：通话与客户/工单关联；录音访问授权；消息失败重试和去重。

### CRM-018 商保中心
交付：保险公司、保单、询价、预授权、材料、邮件收发、人工处理、理赔、对账。
验收：预计赔付与实际到账分离；邮件附件留哈希；每次状态变化可审计。

### CRM-019 运营分析
交付：指标定义、报表、看板、导出审批、组织数据权限。
验收：每项指标有口径说明；导出脱敏；报表结果可追溯数据时间范围。

### CRM-020 系统集成、上线与运维
交付：接口监控、任务监控、备份、恢复、部署脚本、日志告警、运维手册。
验收：备份恢复演练通过；关键接口告警有效；上线回滚方案可执行。

## 5. 建议开发顺序
CRM-001 → CRM-002 → CRM-003 → CRM-004 → CRM-005 → CRM-006 → CRM-007/008 → CRM-009/010 → CRM-011/012 → CRM-013/014 → CRM-015/016/017 → CRM-018/019/020。

## 6. 每个任务的交付模板
- 需求理解与不做范围
- 数据模型及迁移脚本
- API及OpenAPI更新
- 管理端页面
- 患者/员工端页面（如适用）
- 权限矩阵
- 状态机和异常流程
- 单元测试、集成测试、端到端测试
- 部署和回滚说明
- 验收结果与遗留问题

## 7. Git协作约定
- `main`：可发布版本。
- `develop`：集成分支。
- `feature/CRM-xxx-short-name`：功能分支。
- `fix/CRM-xxx-short-name`：缺陷分支。
- 每个任务一个PR；PR描述包含任务编号、数据库迁移、接口变化、测试结果和截图。
- 不允许直接向main推送未审查代码。
