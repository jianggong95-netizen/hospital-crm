# 医院内网部署说明（V1.0基线）

## 1. 推荐部署拓扑
- 医院内网用户区：管理端、医护端、客服端。
- 患者访问区：微信小程序/H5经医院批准的DMZ/API入口访问；若医院不允许外部访问，需规划专用安全接入区。
- 应用区：CRM API、管理端静态资源、AI服务、任务调度。
- 数据区：PostgreSQL、Redis、RabbitMQ、MinIO。
- 集成区：HIS SQL Server只读连接、呼叫中心、短信、支付、商保连接器。
- 运维区：日志、监控、备份、堡垒机和审计。

微信小程序/H5面向院外患者时，不能仅部署在完全隔离的内网；必须由医院网络部门设计DMZ、反向代理、WAF/API网关、访问控制和数据交换边界。不得将HIS数据库直接暴露到互联网。

## 2. 环境划分
- DEV：开发环境，合成数据。
- TEST/UAT：测试和用户验收，脱敏数据。
- PROD：生产环境，真实患者数据。
不同环境使用独立数据库、密钥、对象存储桶和API凭证。

## 3. Docker Compose服务建议
- crm-api
- crm-admin-web
- crm-patient-web（H5）
- crm-ai-service
- postgres
- redis
- rabbitmq
- minio
- nginx
- prometheus/grafana（可选）
实际镜像版本应锁定，不使用 `latest` 作为生产部署标签。生产密码通过环境变量注入或密钥管理，不写入compose文件和Git。

## 4. 网络策略
- CRM应用到HIS SQL Server只开放必要的内网端口和来源IP。
- HIS账号只读，限制到批准的视图/存储过程。
- 数据库端口不对用户网段或外网开放。
- 患者端仅访问API网关，不直连数据库。
- 第三方支付/短信/商保出站访问走医院批准的代理和白名单。
- 所有外部回调必须验签、限流和重放保护。

## 5. 配置项示例
环境变量建议：
- `SPRING_PROFILES_ACTIVE`
- `CRM_DB_URL`
- `CRM_DB_USERNAME`
- `CRM_DB_PASSWORD`
- `REDIS_HOST`
- `RABBITMQ_HOST`
- `MINIO_ENDPOINT`
- `HIS_SQLSERVER_JDBC_URL`
- `HIS_SQLSERVER_USERNAME`
- `HIS_SQLSERVER_PASSWORD`
- `JWT_ISSUER`
- `JWT_SIGNING_KEY`
- `PAYMENT_PROVIDER_*`
生产密钥必须放医院密钥管理系统或受控Secret，不提交仓库。

## 6. 备份与恢复
- PostgreSQL定期全量+增量/WAL归档，备份加密。
- MinIO对象数据与数据库元数据一致备份。
- RabbitMQ持久化队列按业务重要性配置。
- 录音和商保材料按医院留存策略归档。
- 定期执行恢复演练，验证恢复点和恢复时间目标（RPO/RTO由医院确认）。
- 备份副本与生产环境分离，访问权限独立。

## 7. 上线前检查
- 网络分区和防火墙规则审批。
- HTTPS证书和域名。
- 数据库账号最小权限。
- 密钥轮换机制。
- 敏感数据加密、脱敏和审计。
- HIS接口只读验证。
- 支付回调验签和幂等验证。
- 监控告警、日志脱敏。
- 备份恢复演练。
- 安全扫描和渗透测试。
- 小程序备案、隐私政策、用户授权和平台审核事项。
